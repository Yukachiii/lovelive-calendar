LoveLive Calendar

ラブライブ！シリーズに関係するイベントをまとめて確認し、**「行く / 迷う / 行かない」**を簡単に管理するための非公式カレンダープロジェクトです。

公式ライブだけでなく、キャスト個人のイベント、舞台・朗読、ゲスト出演、キャストが参加する別ユニットや音楽活動まで、ファンが実際に「現場候補」として考える範囲を横断して扱うことを目指しています。

このプロジェクトでやりたいこと

ラブライブ！関連のイベント情報は、シリーズ公式サイト、各キャストの公式サイトやSNS、イベント主催者、プレイガイドなど複数の場所に分散しています。

そのため、

• 今月どんなイベントがあるのか
• 自分が行く予定のイベントはどれか
• 申し込むか迷っているイベントはどれか
• 同じ日にイベントが重なっていないか
• 推しているキャストがどこに出演するのか

を一か所で確認できる状態を作ることが、このプロジェクトの目的です。

単なるイベント一覧ではなく、自分の参加予定を中心に見られるカレンダーを目指します。

基本となる使い方

各イベントに対して、参加予定をできるだけ少ない操作で登録します。

|ステータス |意味         |
|------|-----------|
|○ 行く  |参加予定       |
|△ 迷い  |検討中・応募予定を含む|
|× 行かない|不参加        |
|－ 未設定 |まだ判断していない  |

将来的には、参加予定とは別にチケット状況も管理できるようにする想定です。

例:

• チケット確保済み
• 抽選結果待ち
• 未応募
• 一般販売待ち

現在の状態

現在はアイデアと操作感を確認するためのMVPです。2026年9月の掲載データは2026年9月10日、10月は9月9日、11月以降から2027年の掲載データは9月11日時点で、公式サイト・主催者・プレイガイドなどを確認して修正しています。ただし、各年・各月の全イベントを網羅するものではありません。2027年後半など、まだ公式発表のない期間は推測で埋めません。

まずは、

1. イベントを月ごとに確認する
2. キーワード、関連シリーズ、ラブライブ！キャスト、地域、参加ステータス、イベント種別を組み合わせて絞り込む
3. 「行く / 迷う / 行かない」を登録する

という核になる体験を検証しています。

実装は現時点ではシンプルなHTML / CSS / JavaScriptを中心としており、参加ステータスはブラウザの localStorage に保存します。

イベントデータは「1公演・1出演枠＝1レコード」とし、`doorsAt`（開場）、`startsAt`（開演）、`endsAt`（終了）、`eventGroupId`、関連シリーズ配列、出演者配列、会場オブジェクト、公式URL、情報源URL、確認日を分けて保持しています。出演者は情報源どおりの全員を`allCast`に保持し、画面表示と絞り込みに使う`cast`はシリーズ別名簿に一致するラブライブ！キャストだけに限定しています。開場・開演・終了時刻などを公式情報で確認できない場合は推測値を入れず、`null`にします。

キャストの絞り込みはシリーズと連動します。「関連シリーズ」が「すべて」のときはシリーズ別のグループで候補を表示し、特定シリーズを選んだときはそのシリーズのキャストだけを表示します。

画面側はRepository経由でイベントを取得しているため、将来は同じインターフェースの実装を追加してNext.js + TypeScript + Supabaseへ移行できる構成です。会場には住所と将来用の座標フィールドを用意していますが、Mapbox表示はまだ実装していません。

開発方針

このプロジェクトでは、機能を増やすことよりも、まずイベントを見つけて参加判断を記録するまでの手間を減らすことを優先します。

特にスマートフォンから使うことを重視し、イベント1件に対してできるだけ少ない操作で予定を登録できるUIを目指します。
